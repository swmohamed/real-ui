# Internationalization beyond RTL (text, formats, locales)

RTL/Arabic has its own deep track (rtl/*). This file covers the OTHER
i18n cases: non-Arabic multilingual products, and locale-aware formats
inside any language. Labels: ratios are RECOMMENDED heuristics
(W3C i18n-style industry guidance — verify against real target-locale
content before locking layouts). These percentages are synthetic stress-test
budgets, not facts about every translation; real target-language strings and
translator review outrank them.

## Text expansion & contraction (design for the longest language)

| Target vs English UI | Width change (heuristic) | Survival rule |
|---|---|---|
| German / Russian / Finnish | +20–35% (worst: +60% short labels) | min-width + wrap, never fixed-width buttons |
| French / Spanish | +15–25% | same |
| Arabic | +15–30% (see rtl/implementation.md) | bilingual sizing (ux/content-design.md) |
| Chinese / Japanese / Korean | −25–40% width, taller line-height needs | don't rely on width for hierarchy; mind 1.5–1.8 line-height |
| English (from CJK base) | +30–50% | design both directions when originating CJK |

Layout survival kit (any direction):
- Buttons/nav/inputs: min-width + `text-wrap` allowed; no pixel-fixed
  widths tied to source-language text.
- Truncate with ellipsis + full text on hover/focus (title, tooltip) —
  but NEVER at design time: design shows real longest realistic labels.
- Avoid text baked into images; icons carry no text; concatenation in
  code, not in copy ("Hi, {name} {verb}" breaks word order across
  languages — use full-sentence templates per locale).
- Pseudo-localization check: pad labels +25% at design time; if the
  layout breaks, fix the layout, not the translation.

## Locale formats (represent, don't translate)

| Item | Variation | Rule |
|---|---|---|
| Dates | D/M/Y (most) vs M/D/Y (US) vs Y/M/D (CJK/ISO) | localize order + separator; calendar too (Hijri — industries/islamic-apps.md; weekday start Sat/Sun/Mon varies) |
| Time | 24h vs 12h AM/PM | follow locale; keep consistent within data tables |
| Numbers | 1,234.56 vs 1.234,56 (EU) vs ١٢٣٤ (AR contexts) | thousands/decimal separators localize; keep ONE system per surface |
| Currency | symbol position (€10 / 10 € / $10), decimals (JPY 0) | ICU-style formatting; exchange-rate display when crossing markets |
| Names | given-first vs family-first (CJK/HU); single vs multi-word | never hardcode "First/Last"; label per locale |
| Addresses | US street/state/zip vs UK/Japan order vs no-street markets | address block is a locale component, not a fixed form |
| Phone | country code, RTL-safe display | dir="auto" on user-entered numbers |

Pluralization & gender: many languages have 2+ plural forms (RU/AR
6 forms; PL has forms for 2–4). Never concatenate "({n} items)" — use
per-locale plural templates ("{n, plural, one {# item} other {# items}}").

## When this file vs rtl/*

- Arabic or any RTL script → rtl/* files lead; this file adds expansion
  ratios + formats.
- LTR multilingual (EN+DE/FR/ES…) or single-market non-English → this
  file only.
- Locale formats inside an English product (dates/currency for EU
  market) → Formats table above.

## i18n QA (finish-gate excerpt)

- [ ] Longest-language check done (+25% pad) — no clipped labels
- [ ] No text in images; concatenation-free sentences
- [ ] Dates/numbers/currency match target locale; one system per surface
