# Page Type: Product / Detail Page (PDP, Game Page, Listing)

The decision page: everything that resolves "is this the one?"

## Decision requirements and candidate regions

Select regions from the actual decision model and content inventory. The
order below is a checklist, not a template: a property, article, medicine,
and game require different evidence, risks, actions, and priority. Omit
unsupported ratings, reviews, commerce controls, recommendations, and trust
claims.

1. **Identity**: breadcrumb, title (h1), key meta (brand/author/studio/
   location), rating + count, share
2. **Evidence media**: gallery (zoom, swipe, video, 360°, floor plans by
   vertical) — the largest surface on the page
3. **Decision block** (the buy box): price + variants/options + primary
   CTA + trust chips (delivery, returns, warranty, cancellation)
4. **Depth content**: description (scannable, not walls), specs/amenities
   as structured tables or definition lists, requirements
5. **Social proof**: reviews with distribution histogram + photos, Q&A
6. **Context**: related/similar/recently viewed
7. **Sticky decision bar** on mobile (price + CTA persist)

## Vertical specifics

- **Ecommerce PDP**: variant matrix (size × color with stock-aware
  disable states), size guide modal, delivery-date promise, payment
  methods incl. COD/BNPL chips (MENA), bundle/upsell strip
- **Game page (portal)**: huge play CTA or embed iframe, description,
  controls list, developer, related-by-tag shelf — friction-to-play ≈ 0
- **Game page (store)**: media (video+screens), price/bundle selector,
  system requirements table, achievements, DLC list, reviews
- **Real estate listing**: gallery + floorplan tabs, key-facts icon bar,
  description, amenities checklist, map + POIs, agent card + WhatsApp/
  call, payment plan (offplan MENA), similar listings
- **Hotel/property**: room-type cards each with own rate selector +
  cancellation policy per rate, sub-score summary
- **Course / learning offer**: match the education family before picking regions. A marketplace course may need instructor + ratings + syllabus + price; a bootcamp needs outcomes, dates, and application; open courseware needs the materials packet (syllabus/calendar/videos/notes); a tutor profile needs the person, availability, and languages. A syllabus accordion is one candidate, not the default.
- **Restaurant item (dialog-page hybrid)**: photo, options groups with
  required indicators, quantity, notes field, add-to-cart with total
- **Article/event/movie detail**: poster/hero, key facts (date/venue/
  runtime), CTA (tickets/watch/read), credits/cast, related

## Decision psychology rules

- Price near CTA, total honesty early (shipping/fees visible pre-cart)
- Stock/urgency only when real ("3 left" from inventory, never fabricated)
- Reviews: show distribution (5★ ████ 320) not just average; newest/
  verified filters; owner responses add trust
- Escape hatches: "not sure?" links to comparison/guide (retains user
  instead of losing them to a competitor tab)

## Mobile behavior

- Gallery = swipe full-width, thumbnails as dots; zoom pinch
- Sticky bottom bar: price + CTA (+ variants shortcut if selection
  incomplete → scrolls to selector with highlight pulse)
- Specs collapse to accordions; Q&A to tabs
- Media-first ordering: image → title/price → CTA → details

## RTL/Arabic

- Gallery order right→left; variant chips RTL; price displays with
  Western digits + Arabic currency (ر.س / ج.م / د.إ)
- Delivery promises in Arabic ("التوصيل خلال يومين") with icon
- Reviews in Arabic first (sort by language relevance), English reviews
  secondary
- WhatsApp CTA standard for high-touch verticals (real estate, B2B)

## Anti-patterns

- Media that requires login
- Spec sheets as images/PDFs
- Variant selection that silently fails (must disable out-of-stock combos)
- Related sections that outrank decision info
- Fake countdowns
