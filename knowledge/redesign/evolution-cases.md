# Redesign: Evolution Reasoning (how real products change well)

Method file: teaches REASONING about product evolution from
observations — not copying famous redesigns. Label discipline is
strict: real-case claims carry their source class; generic reasoning
is DESIGN PRINCIPLE / RECOMMENDED.

## The evolution lens (OBSERVATION → PATTERN → PRINCIPLE → APPLICATION)

For any studied product change, extract in this order:

1. OBSERVATION — what concretely changed (IA? nav model? type system?
   density? states?) and what provably survived (logo, color, terms).
2. PATTERN — which class of change: system-maturation (tokens unify),
   platform-alignment (native idioms adopted), scope-shift (product
   grew a marketplace/community/finance layer), trust-ladder (security/
   compliance surfaces added), density-cycle (air ↔ data as audience
   shifted).
3. PRINCIPLE — the transferable rule ("brand constants survive system
   overhauls"; "new business layers import their industry's UX bar —
   trust UX upgrades ride with monetization").
4. APPLICATION — how it maps to THIS project (redesign/workflow.md stages).

## Corpus-observed evolution signals (v1+v2 evidence)

- PayPal Arabic portal: logical-properties + `rtl:` variants adopted
  over time (system maturing toward RTL correctness) `[OBSERVED - v1
  corpus]` → pattern: maturation = internal consistency upgrades that
  users feel as "cleaner" without knowing why.
- Coinbase `--cds-` token system across surfaces `[OBSERVED]` →
  pattern: mature products tokenize; redesigns that skip tokens decay
  again (why workflow stage 6 exists).
- Kraken's dedicated mono family for market data `[OBSERVED]` →
  pattern: content-type-specific typography arrives with data-depth
  maturity, not v1 products.
- flynas custom brand font + Font Awesome stack `[OBSERVED - v21]` →
  pattern: budget-carrier identity through type, not imagery-heavy
  luxury codes (industry honesty — see travel-tourism.md).
- Bayt bilingual single-family stack (Vazirmatn) `[OBSERVED]` →
  pattern: bilingual products mature toward one family covering both
  scripts (consistency beats per-script "perfect" picks) — same
  conclusion as typography/responsive-pairing.md.

## Anti-evolution patterns (how redesigns go wrong)

| Failure | Signature | Guard |
|---|---|---|
| Identity wipe | users say "where is X?" | redesign/preservation.md recognition tests |
| Trend import | glassmorphism/gradient wave with no product reason | originality.md refused-list |
| Scope cosplay | redesign adds marketplace/community visuals with no flows | diagnosis-first |
| System debt | new screens on new tokens, old screens untouched | prioritization.md staged shippability |
| Feature burial | IA change pushes power features deeper | diagnosis.md interaction cost |

## Applying evolution to staged redesigns

Evolution = SERIES of coherent steps, each shippable (prioritization.md).
Prefer: systemize (tokens) → repair (states, a11y) → restructure (IA/
nav) → distinguish (visual direction) — unless diagnosis says brand
damage is the product's problem, then direction first with explicit
transformation brief.

## Honesty contract

Never present a famous-company redesign story as evidence unless it
was actually observed this session (spec rule). Corpus cases above
carry file evidence; everything else stays framework, not folklore.
