# Industry: Education & EdTech

## Characteristics
Two audiences: learners (motivation-sensitive) and institutions/parents
(buyers). Outcomes are the product; proof = completion + results + employers.
Progress representation is structural when the learning model needs it.
Streaks, hearts, and leaderboards are habit-product patterns, not a
category default.

## User intents
1. Learn a skill (course/program discovery)
2. Evaluate quality (instructor, syllabus, reviews, certificates, price)
3. Start/continue learning (player, exercises, progress)
4. Prove learning (certificates, assessments)
5. Teach/administer (instructor dashboards, LMS)

## Business goals
Enrollments/subscriptions (B2C), seat licenses (B2B/2School), completion →
renewal, institutional procurement cycles.

## Candidate information-architecture patterns (not a product sitemap)
- Consumer catalog (one candidate, not a default): Home (value + catalog
  preview) → Browse (subject tree) → Course page (syllabus, instructor,
  reviews, preview lessons, price/enroll) → Learning surface → proof.
  Other families use exam clocks, tutor calendars, path maps, class
  assignments, or practice queues instead.
- MOOC OBSERVED (Coursera): `--cds-` token family, degree vs course vs
  professional-track IA, enterprise tab, search-first
- Duolingo-class apps: unit path maps, XP/streak systems, hearts (lives)
- Institutional: program finder, accreditation pages, faculty, admissions
  funnels (multi-step applications with document uploads)

## Navigation
- Browse by subject (Business, Data, Design…) + level filters (Beginner/
  Professional) + language filters (Arabic courses as a facet in MENA)
- Persistent "My Learning" for logged users; cart for paid catalogs
- Almentor OBSERVED (AR video-learning): Inter + Noto Kufi Arabic pairing,
  Material icons, search + category rails, subscription CTAs (اشترك)

## Candidate components observed in the genre
- Course cards: provider logo, title, level chip, rating + count, duration,
  price/audit tag, "bestseller" flags
- Syllabus accordions (modules → lessons with durations + preview locks)
- Instructor panels with credentials + follower counts
- Learning player: chaptered video, speed, captions, transcripts with
  click-to-seek, note-taking, downloadable resources
- Progress: module completion rings/checklists, streak calendars
- Certificates with share/verify links (LinkedIn integration)
- Pricing: subscription vs per-course toggle; financial-aid links (MOOC
  convention); cohort start dates (bootcamp convention)

## Visual characteristics
- Consumer: bright friendly accents on white (Coursera blue #0056D2 OBSERVED
  theme-color), rounded 8–12px, illustration-tilted for kids/language
  (Duolingo green/featherweight illustration), 3D-mascot energy
- Institutional/professional: deep navy/burgundy heraldry, serif display,
  dense degree tables
- Arabic platforms: Kufi headers for modern energy (Almentor OBSERVED),
  Naskh body for long reading (Edraak OBSERVED Naskh-class reading)
- Imagery: real learners/instructors > stock; kid products use illustration

## Interaction patterns
- Preview lessons free (try-before-enroll standard)
- Quiz/exercise loops with instant feedback + explanation
- Progress persistence across devices; resume banners ("Continue where you
  left off")
- Cohort/community: discussion forums per course, cohorts, mentor sessions
- Enrollment funnels with multi-step forms + payment plans

## Mobile patterns
- Downloadable lessons/offline; audio-mode for language learning
- Streak widgets on home; quick 5-minute session CTAs
- Kids: giant touch targets, no hamburger (visible tabs)

## Arabic/MENA considerations (OBSERVED Edraak/Almentor)
- Arabic catalog facets: subtitle/dubbed language filters; religious-
  studies categories on generalist platforms
- Women-oriented learning verticals exist (segment awareness)
- Pricing sensitivity: free/audit + local payment (Fawry, STC Pay) +
  installment display
- Teacher-centered trust: instructor photos/bios in Arabic carry more
  weight than institution badges (talent culture)
- Bilingual certificates (name in Arabic + English) for employer sharing

## Conventions to evaluate (adopt only when model-supported)
Subject-tree browse, rich course pages with preview, syllabus accordions,
ratings-with-count, certificates, progress/resume, financial-aid honesty,
instructor credibility panels.

## Overused/anti-patterns
- Generic "unlock your potential" heroes with stock graduation caps
- Giant education hero, purple/blue gradient, or rounded-card-everything
  as a default "modern academy" look
- Identical LMS dashboards and identical lesson players across families
- Universal sidebar + course-card grid as the only discovery model
- Generic progress circles or motivational gamification on every product
- Locking syllabi behind signup
- Autoplay video with sound on course pages
- Gamification without learning-science (points for watching = hollow)
- Hiding total price/hours commitment

### Learning journey (only the stages THIS product has)

DISCOVERY → EVALUATION → ENROLLMENT → LEARNING → PROGRESS → ASSESSMENT →
COMPLETION → CONTINUATION is a checklist, not a sitemap.

- Discovery/evaluation dominate public web evidence (this wave).
- Learning/progress/offline dominate Play listing claims.
- Assessment is central for exam-prep, HackerRank, NPTEL/SWAYAM exams,
  certificates — absent for HelloTalk or Photomath.
- Completion may be a credential, a hired job (bootcamp), a passed exam,
  a maintained streak, or simply “understood this problem.”
- Continuation: next cohort, next skill, next live batch, next card —
  family-specific.

  membership quietly present (Plus).
- Academies (Platzi, Alura, Rwaq): school voice, path/career, local language.
- Bootcamps: outcome and program structure over card grids.
- Habit language apps: playful only when the model is daily play; still
  typographic discipline (modern-craft.md).
- Exam-prep: exam names and live state outrank lifestyle heroes.
- LMS/classroom: operational density; vendor marketing sites stay sales
  pages and must not be copied as student UI.
- Open courseware: typographic, material-first, low commerce chrome.
- Arabic/RTL: Rwaq `lang=ar dir=rtl` with Arabic course rails; Edraak
  listing still claims offline/certificate on Android. Mixed Arabic/English
  technical terms need `lang` on spans (accessibility/floor.md). Do not
  flip Latin code samples.

Avoid as unearned defaults: giant education hero, purple/blue gradients,
rounded-card-everything, identical progress rings, identical players,
identical mobile card stacks, generic AI polish
(anti-patterns/ai-aesthetics.md).

### Accessibility, localization, RTL

STANDARD REQUIREMENT / PLATFORM RULE where WCAG/platform applies;
DESIGN PRINCIPLE for learning-specific application:

- Captions and transcripts belong to **video/audio lessons** (edX listing
  names transcripts). They are not decoration. Keyboard access to playback,
  speed, and transcript seek is required when a player exists.
- Quiz feedback must not be color-only; errors need recovery, not only XP
  loss.
- Progress must have text/semantics, not only rings.
- Reduced motion: no confetti-as-default (already in ux/states.md for
  Duolingo-class products — keep it family-gated).
- Photomath/ELSA/Classroom camera or mic: purpose-first permission, denial
  path (`ux/mobile-states.md`).
- Certificates: bilingual names, Western vs Arabic-Indic digits per market,
  Gregorian (+ Hijri only if official). Do not invent a certificate.
- RTL navigation follows content direction; course codes, IDE samples, and
  equations stay LTR inside RTL chrome.

### Routing (never “course → one template”)

Classify EDUCATION + family + user (learner / parent / teacher / L&D /
creator) + learning model + content model + business model + platform.
Then retrieve this file with the matching row — not a universal academy
layout.

Future upgrades: inspect this corpus and add products that introduce a
new learning model, platform behavior, region, business model, or a11y
pattern. 20+ mobile and 20+ web is the floor, not the finish line.
