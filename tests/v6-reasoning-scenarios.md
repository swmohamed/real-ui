# V6 Reasoning Scenarios

Method: this is a **reasoned scenario specification**, not an executable UI,
browser, native-app, accessibility, or usability test. For this audit, fresh
ephemeral Codex sessions receive only the current REAL-UI skill and are asked
for compact design contracts without browsing, implementation, or file edits.
The repository report records observed run outcomes separately.

The expected result is a decision contract, not one required layout. A run
fails when it invents scope, copies a generic shell, hides authority or shared
state, misstates operation recovery, treats phone/tablet as scale variants, or
claims runtime/render evidence.

| ID | Scenario | Required reasoning | Primary failure traps |
|---|---|---|---|
| S1 | Arabic Egyptian transfer assistant; preparer/approver; fraud-review wait; fee-reservation partial failure; phone/tablet | high-consequence proposal/commit boundary, roles, provenance, durable transaction state, RTL/native adaptation | chat-first, autonomous submit, approval=success, spinner, mirrored-everything, stretched phone |
| S2 | Collaborative web/iPad spatial research board; concurrent edits, offline work, automation adding source notes | spatial artifact, role/actor model, anchored discussion, sync/stale/conflict/history, automation attribution | avatar row as completeness, card dashboard, last-write-wins without warning, hidden automation |
| S3 | Bilingual warehouse inventory import on rugged Android phones and desktop web; 20k rows; partial validation and canceling | bulk operation identity, source/schema, staged validation, table/detail adaptation, partial results, safe retry/cancel | upload spinner, fake percentage, every row as mobile card, destructive retry |
| S4 | Arabic-first education tutor that explains supplied lessons and cites them but cannot grade or change records | retrieval/synthesis scope, sources/freshness, editable learning artifact, uncertainty/recovery, age/accessibility | universal chat, invented grading/profiles/gamification, fake confidence |
| S5 | Shared care-plan review on iOS/Android/tablet; clinicians suggest, senior clinician approves; no AI | permission/consequence, suggestion versus commit, version/conflict/history, native and accessible status | direct edit for everyone, presence=control, generic social comments, invented automation |
| S6 | FULL redesign of a deployment console whose existing capabilities include environments, queued/running logs, cancel, retry, rollback, approvals, comments, and audit history | extract capabilities/contracts, quarantine old presentation, re-derive operations-first structure, hard redesign gates | cosmetic reclothe, capability loss, conflated recovery verbs, invented analytics/chat |

## Cross-scenario acceptance

- Every run starts from classification, explicit scope, and a product model.
- AI is absent in S5 and constrained differently in S1, S2, and S4.
- Collaboration control differs across maker/checker, spatial co-editing,
  clinical approval, and deployment review.
- Operation representation differs across payment, import, and deployment.
- Phone, tablet, desktop, web, iPad, Android, and native mobile choices state
  what changes—not only a breakpoint or stack.
- Cards, chat, side panels, dashboards, percentages, confidence, approvals,
  and notifications appear only when justified by the modeled task and known
  capability.
- Each run labels assumptions and uncertainty; none claims runtime/render
  validation.
