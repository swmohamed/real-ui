# Security Policy

## Reporting a vulnerability

Do **not** post security vulnerabilities as public GitHub issues, discussions,
or pull requests.

Use GitHub Private Vulnerability Reporting / Security Advisories when it is
available on this repository:

https://github.com/swmohamed/real-ui/security/advisories/new

If private reporting is not available, contact the repository owner through
GitHub without including exploit details in a public channel.

## What to include

A useful report typically includes:

- a description of the vulnerability and its impact
- the affected files, install path, or commit when known
- steps to reproduce, or a proof of concept if you have one
- any workaround you already know of

Do not include secrets that are not yours. Redact tokens and private data.

## Responsible disclosure

Please keep the report private until maintainers have reviewed it and a fix
is available, or until they say it is safe to discuss publicly.

Maintainers will review private reports and, when a report is valid, prepare
a fix and publish a GitHub Security Advisory if that is appropriate.

## Scope

This policy covers the REAL-UI repository: skill files, scripts, tests,
install tooling, and published GitHub artifacts.

It does not cover third-party products used as research evidence, or copies
of this skill installed into other agents’ skill directories.

## Safe harbor

Good-faith vulnerability research is welcome. Do not access data that is not
yours, disrupt maintainers or users, or use a finding for anything other than
notifying this project.
